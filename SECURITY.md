# Security policy

## Reporting a vulnerability

Do not open a public issue for a suspected vulnerability. Do not include
credentials, personal data, signed URLs, tokens or private documents in a
report.

Contact a repository maintainer privately and include:

- a concise description of the issue;
- the affected route, component or version;
- safe reproduction steps;
- the possible impact; and
- a suggested mitigation, if available.

Maintainers should acknowledge the report, assess its impact, prepare a fix
and coordinate disclosure after affected deployments are updated.

## Supported versions

Security fixes are applied to the default branch and the currently deployed
version of the application.
